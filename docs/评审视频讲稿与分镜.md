# 第一部分：项目事实核对

## A. 作品定位

浏览器端互动展项：观众站在摄像头前，用手直接驱动皮影戏幕布上的皮影，并用手势推进剧情。
非视频播放、非预制动画——每一帧都是按手部关键点实时求解的关节姿态。

## C. 最有价值的 2–3 项创新（均有实现与画面支撑）

1. **把"三根竹签"的操作逻辑搬到手上，而不是用手势切动画**
   张手=跟手、握拳=执签定住、两手一合=作揖、双手举高=亮相、手掌横移=走位；
   进阶模式按传统握法：拇指食指捏合=夹住竹签、两指连线转动=搓签转腕。
   依据：传统皮影三根签的分工（平衡杆握法、动作杆在拇指食指间与中指无名指小指间），见 `docs/手指控制调研.md`。
   实现：`app/show.js` `drivePuppetWithHand()`、`app/puppet.js` 手腕转轴、`app/gesture.js` 捏合距离与搓动角。

2. **动作即台词：剧情由手势推进，而不是时间轴自动播完**
   每一出戏的节拍带 `cue` 字段，观众做出对应动作（作揖/举高/甩袖）才进入下一句；
   一次动作只推进一步（松开才计数），屏幕给绿色「✓ 已认出」与音效反馈。
   实现：`app/show.js` `updateBeats()`、`cueLatch` 防连跳。

3. **一只手管一个皮影：左右手分控，手掌横移即走位**
   左手管左边皮影、右手管右边皮影，每只手只驱动同侧一条手臂，另一条自然垂落；
   目标位置 = 手掌横向位置 × 0.95，带死区，握拳时站住。
   实现：`app/show.js` `splitHands` 分支。

# 第二部分：完整配音讲稿

> 约 1080 字，正常语速约 4 分钟；配合约 30 秒无旁白演示画面，成片约 4:20。
> `〔画面〕` 内为提示，不朗读。

〔0:00–0:18｜无旁白，只有画面与字幕〕
画面：真人举起双手，幕上皮影随之抬手、两手一合作揖；切到"亮相"定格。
字幕：**举起双手，皮影跟着你动。**

〔0:18–0:50｜定位与背景〕
皮影戏是入选联合国教科文组织人类非物质文化遗产代表作名录的传统戏剧。
它的魅力不在"看"，而在"耍"——艺人一手执三根竹签：一根撑头颈身，两根挑双手；
靠拇指和食指搓动签杆改变关节朝向，靠抬落平衡杆让皮影进退。
但这门手艺要练很多年，观众在展厅里通常只能隔着玻璃看。
我们想做的，是让观众站到幕布前，用自己的手，把一台皮影戏演出来。

〔0:50–1:45｜核心创新〕
第一个创新，是我们没有把"手势"当成翻页开关，而是把三根竹签的操作逻辑搬到了手上。
张开手掌，皮影的手跟着你走；握拳，这只手就"执签"定住，不再跟手；
两手一合是作揖，双手举高是亮相，手掌左右平移，皮影就迈步走位。
更进一步，我们还按传统握签的方式做了一套手指模式：
拇指和食指捏住，等于夹住一根竹签；两指连线转动，就是传统里的"搓签"，皮影的手腕会跟着转。

第二个创新，是动作即台词。
台词不是按时间轴自动播完的。屏幕上会浮出一个提示，比如"两手一合·作揖"，
你必须真的做出这个动作，戏才往下走一句。做对了，提示会变绿打勾，还给一记锣鼓。
观众为了看下一句，会主动去学这个动作——这时候"教"就发生在"演"里面。

〔1:45–3:20｜关键实现与实际成果〕
（约 10 秒无旁白：只放完整交互链路——举手、跟手、作揖推进、亮相）

舞台这一层，我们没有播放预制动画。
每一个皮影都是分件、关节加竹签的结构，我们逐帧计算每个部件的变换：
肩和肘用两段骨骼的逆解求解，手腕跟随手部关键点，所以皮影的手是真的在"够"你的手。
同一套骨架还能切三种皮：剪影、镂空、套色。

内容上做了六出戏，三出原创、三出改编自西厢记、霸王别姬和八仙过海，一共二十五个剧情节拍。
六出演完，会自己演一段二十四秒的谢幕，作揖、亮相、换位、再拜，不需要人管。

第一次来的人不会用，所以我们做了教学关：五步，每一步都必须真的做出来才通过，
学完这一遍，下次进来直接开演。手指模式有另一套五步教学，讲的是捏住、松开、搓动。

声音方面，六出戏各配了一段戏剧原声——昆曲牡丹亭、将军令、夜深沉、水龙吟、万年欢、良宵引。
换幕时旧曲淡出、新曲淡入，不会硬切；作揖、亮相这些动作有对应的锣鼓音效。
原声里本身有唱腔，所以台词配音默认关闭，避免两层人声打架。

现场落地这块，我们做了三件工程上的事：
一键启动并自动打开浏览器；展馆模式全屏、隐藏鼠标、屏蔽右键、出错自动重载；
还有摄像头自检、音频自检和实时诊断面板，不接技术也能自己看出问题在哪。

〔3:20–4:05｜创作过程与原创贡献〕
开发过程中，我们先把传统握签的资料读清楚，也对比了现有的手势互动作品——
大部分是挥手翻页、隔空点击，和皮影的操作逻辑没有关系。
所以方案定下来的时候，我们放弃了几种看起来更"炫"的做法：
没有做五指各控一根签，因为普通摄像头对小指和无名指的抖动太大；
也没有把台词做成自动播放，那样观众就只是看客。
这些取舍，是这个作品和"手势控制动画"最不一样的地方。

测试上，我们写脚本逐项验证：五步教学能不能通过、剧情节拍会不会连跳、
音频电平是否一致、不同分辨率下按钮会不会挡住标题。
真机上，用摄像头反复调执签和捏合的灵敏度。

需要说明的是，代码是在 AI 编程助手的协助下完成的；
选题、交互设计、素材选用与授权、测试验收和部署，由我完成。

〔4:05–4:20｜价值收束〕
它不需要深度相机，也不需要穿戴设备，一台普通笔记本加一个摄像头就能跑，断网也能用；
换一套皮影资产，就能换一批角色。
对非遗展陈来说，它把"看戏"变成了"学艺"。

## 必须补充验证（录之前先跑一遍）

1. 真机捏合阈值：`?finger=1` 走教学关第 2 步，若"捏住皮影不动"说明阈值太严（调大 `show.gripThreshold`），"没捏就动"说明太松；
2. 双人模式：`?duo=1`，两人站定不交叉手臂，确认两只手各控一个皮影；**若不稳定，视频里就不要放双人段落**；
3. 音频：先开 `audiotest.html` 确认 6 段原声都能响，再录，避免录到静音。

## 匿名化检查（容易违规的地方）

| 风险点 | 处理 |
| --- | --- |
| 浏览器地址栏出现 GitHub 用户名 | 录屏统一用 `http://127.0.0.1:5173/`，**不要**录在线版地址 |
| 书签栏、历史记录、桌面文件名 | 录屏前开一个新的 Edge 窗口（或 kiosk 模式），隐藏书签栏 |
| 微信/QQ/邮箱弹窗 | 关闭通知；用"专注助手"或全屏录制 |
| 屏幕上的文件路径含真实姓名 | 项目路径若含姓名，先改目录名再录 |
| 片中署名 | 只写作品名，不写学校、姓名、指导教师 |
| 台词/字幕中的地名机构 | 剧本里没有，保持即可 |

## 建议的录制顺序（约 1.5 小时可完成）

1. 先跑一遍 `audiotest.html` + `camtest.html`，确认声音与摄像头正常（5 分钟）；
2. 按 R1 → R3 → R4 → R5 → R6 → R2 录屏（约 40 分钟，每条录 2 遍）；
3. 可选手机拍 P1（10 分钟）；
4. 按第三部分表格剪辑，先对时间轴贴旁白，再补字幕与放大特写（约 40 分钟）；
5. 导出 1920×1080 / MP4 / H.264，检查时长 ≤ 4:40、音量一致、无个人信息。
