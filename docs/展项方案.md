# 「掌中戲」数字皮影互动展项 · 方案说明

> 一句话：观众站在灯箱前举起双手，屏幕里的皮影就跟着他抬手、落步、亮相；握拳是执签，双手握拳可以定格留影。
>
> 技术底座：Woooo Piying Lab 官方皮影资产 + Google MediaPipe 手势识别 + three.js 实时渲染，全部跑在一台普通电脑的浏览器里，断网可用。

---

## 一、展项构成

```
[ 摄像头（屏幕上方/下方） ] ──USB──┐
                                  ▼
                        [ 展项主机（迷你 PC） ]
                                  │ HDMI
                                  ▼
                        [ 竖装/横装大屏 + 灯箱外框 ]
```

现场只有三样东西：**一块屏、一个摄像头、一台小主机**。所有内容本地运行，不需要网络、不需要灯控联动、不需要专用传感器。

### 硬件建议

| 项 | 建议 | 说明 |
| --- | --- | --- |
| 屏幕 | 55–75 寸 4K，或 3×2 拼接 | 16:9 或 16:10；亮度 ≥ 500nit，馆内灯光下皮影才够"透" |
| 主机 | 迷你 PC，i5 / R7 以上，**带独显更稳** | GPU 跑 WebGL 阴影与 MediaPipe GPU delegate；无独显也能跑，帧率会降到 ~30 |
| 摄像头 | 1080p USB 摄像头，**广角优先**（视场 ≥ 78°） | 观众离屏 1.2–2.2 m 时要能看全双手；固定焦距、关掉自动对焦更稳 |
| 摄像头位置 | 屏幕正上方中央，**略微下俯 10–15°** | 与观众视线接近，抬手动作不被裁切 |
| 灯光 | **观众区正面补光**（不打屏幕） | 手势识别靠轮廓，逆光/大背光会让手部检测掉帧；但别直射屏幕，否则剪影发灰 |
| 外框 | 木框 + 灯箱内衬（可现做） | 屏幕上留 10–15% 边距给字与提示，不要贴边 |

### 尺寸与视距

- 观众站位标线：距屏 **1.5 m**（地面贴一对皮影脚印，比文字提示有效得多）
- 有效识别范围：画面中央 **70%** 区域，横向覆盖约 ±0.9 m
- 摄像头画面在右下角小窗镜像显示（可关），让观众知道"自己被看见了"

### 单人版 / 双人版怎么选

| | 单人版（默认） | 双人版（`?duo=1`） |
| --- | --- | --- |
| 站位 | 正中一条标线 | 左右两条标线，间距 ≥ 1.2 m |
| 摄像头 | 普通 78° 广角够用 | 需要 **≥ 100° 广角**，或把机位后移到 2.5–3 m，否则两人的手会贴到画面边缘 |
| 推理开销 | 2 只手 | 4 只手，约 1.6–2 倍；无独显机器先测帧率 |
| 观众关系 | 一个人演，对手自动接招 | 两个人对打/对舞，停留时间明显更长，但要有工作人员引导站位 |
| 风险 | 低 | 两人交叉手臂会让左右身份互换（程序按画面横向顺序分人） |

**建议**：先按单人版验收交付，双人作为"周末/节假日模式"用第二个快捷方式（`start-kiosk-duo.cmd`）切换，避免平时没人配合时画面空一半。

## 二、观众动线（30 秒上手 / 3 分钟玩透）

1. **待客**（无人）：皮影自动轻轻摆动，中央一枚朱红圆环呼吸，"举手 · 开演"。
2. **唤醒**：观众抬手 → 圆环填满 → 锣声、3-2-1 → 开演，字幕打出「一盏灯，一张皮。两手执签，便有了悲欢。」
3. **执签**（核心）：张手移动 → 皮影双手跟着走；握拳 → 定住。走快了皮影会自己迈步。
4. **换出**：双手举过头顶 → 锣鼓过场 → 下一出（庭院 / 校场 / 云山，共三出）。
5. **留影**：双手握拳 1 秒 → 落朱印、闪一张"戏照"，4 秒后收回到戏台。
6. **收幕**：人离开 6 秒 → 皮影作揖退场，回到待客循环。

**为什么只教 4 个动作**：博物馆观众平均停留 40–90 秒，动作超过 4 个就记不住。握拳/张手是本能动作，不需要学习；"双手举过头"用于换出，避免误触；"双手握拳"用于拍照，需要刻意做两次，不易误触发。

## 三、内容生产（馆方自己想加角儿怎么办）

Woooo Studio 的插件（Blender / Unity / AE / Godot / Figma）就是这条内容链路的入口：

1. 在 **Blender 插件**里导入 `.woop` 资产，调骨骼、用「灯箱」面板做背光、用「滤镜」面板加暗角与辉光，渲染宣传片或宣发图；
2. 新的皮影角色在 Woooo 平台导出 `.woop`；
3. 把 `.woop` 丢进本项目的 `puppets/`，在 `puppets/index.json` 里加一行，在 `app/show.js` 的 `SCENES` 里配一下站位即可 —— **不需要重新绑骨**，关节与 IK 由 `rig.js` 自动解析 `woop.json`。

一场新戏的平均工作量：**换角儿 10 分钟，设计一个新动作/新景 1 小时**。

### 两种皮影观感（现场可切）

- **纯剪影**（默认）：黑色皮影 + 暖色背光幕布，最接近传统影窗，远看辨识度最高；
- **剪影 · 镂空**：剪影上带雕刻孔，背光从孔里透出来，近看像真皮影的"透雕"；
- **套色彩绘**：按角色染色（朱红身、石绿袖、墨蓝腿、赭石脸手），衣袍上同样有雕刻孔，像剪纸套色/彩绘皮影。

现场按 `K` 键循环切换，或网址加 `?skin=carved|painted|silhouette` 固定。不需要换资产、不需要重启。

**建议**：按展期主题选一种定死，别让观众自己在几档之间切——会影响"这是一件什么作品"的判断。
- 讲"老影窗、灯箱" → 剪影 或 剪影·镂空（远看静、近看有细节，最稳）
- 讲"皮影的色彩与雕刻" → 套色（近看最抓人，但远看辨识度略低）

如果馆里要**真正的传统彩绘皮影**（带具体纹样、人物面部开脸），程序化镂空只能近似，最终还是要：① 请 Woooo Studio 出彩色 `.woop`（格式不变，本项目零改动）；② 或按馆藏实物重绘部件图。

## 四、现场部署

### 开机自启（Windows）

1. 装好 Edge/Chrome；
2. 把 `tools/start-kiosk.cmd`（双人版用 `tools/start-kiosk-duo.cmd`）放到 `shell:startup`；
3. 双击一次，之后每次开机自动全屏开演。

脚本做的事：起本地服务器 → 用 Edge 的 `--kiosk` 模式打开 `?kiosk=1`（双人版再加 `&duo=1`）。

```bat
:: tools/start-kiosk.cmd      单人版：?kiosk=1
:: tools/start-kiosk-duo.cmd  双人版：?kiosk=1&duo=1
```

`?kiosk=1` 会自动：隐藏鼠标、屏蔽右键与快捷键、开启全屏、脚本加载失败 4 秒后自动重载。

### 摄像头权限

第一次需要允许摄像头。Edge 会记住该来源的授权；若被策略拦截，可用启动参数：

```
--use-fake-ui-for-media-stream   （不推荐，仅调试）
```

正式环境建议在组策略里为 `http://127.0.0.1:5173` 预授权摄像头。

### 稳定性

| 风险 | 处理 |
| --- | --- |
| 摄像头被拔 / 被占用 | 自动降级为键鼠模式并给出提示，不白屏 |
| 页面崩溃 | kiosk 模式下监听 `error` 自动重载 |
| 长期运行内存增长 | 无逐帧分配（矩阵复用）、无新增贴图；建议每晚定时重启一次 |
| 观众挡住摄像头 | 双手不可见 6 秒自动收幕，不会卡在某个姿势 |
| 环境光变化 | 识别阈值用张开度比值（尺度无关），并留了 `gesture.js` 的置信度参数可调 |

### 建议日常检查（保洁/值班表上的一行）

- 屏幕上是否还是"举手 · 开演"的待客画面（说明没崩）
- 摄像头小窗里有没有画面（说明摄像头没掉）
- 站在标线上举一次手，看皮影是否跟着动

## 五、性能与指标（实测环境）

| 指标 | 数值 |
| --- | --- |
| 首屏可交互 | 本地约 2–4 s（15 个皮影包 + 8 MB 模型 + wasm，全部本地） |
| 手势延迟 | 摄像头 30fps + 模型推理约 15–25 ms，端到端 < 120 ms（体感"跟手"） |
| 渲染 | 每帧 2 个皮影 × 11–12 块 + 3 个景片，桌面 GPU 稳定 60fps |
| 识别距离 | 1.2–2.5 m 最佳，2.5–3.5 m 可用（画面缩小，仍能判手型） |

## 七、进阶路线（预算/时间允许时）

1. **真彩皮影**：换成彩色 `.woop`，或加染色层 + 半透明皮革质感 shader（背光透射）。
2. **双人对戏**：支持两位观众各控一个皮影（MediaPipe 支持 numHands=4，代码里 `support` 已留接口）。
3. **唱腔与锣鼓**：接真实碗碗腔采样与现场音效，`audio.js` 换成采样播放即可。
4. **扫码带走**：留影后上传，生成二维码，观众手机取图（需一个小后端）。
5. **内容联动**：把馆藏皮影实物做成 3D 扫描件，作为"数字分身"放进同一套骨架。
