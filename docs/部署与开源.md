# 部署与开源：怎么上传、怎么上线、有什么坑

> 结论先说：**本地部署已经是最优解，公网部署可以做但有两个硬前提（版权 + 体积）。**

---

## 一、本地部署（已就绪，推荐作为展馆正式运行方式）

展馆现场要的是"通电即演、断网也能跑、崩溃自愈"，这些本地都已实现：

| 场景 | 做法 |
| --- | --- |
| 日常启动 | 双击桌面「掌中戏 · 手势皮影」快捷方式（或 `启动掌中戏.cmd`） |
| 开机自启 | 把快捷方式拖进 `shell:startup` |
| 展馆全屏 | `启动掌中戏.cmd kiosk`（全屏、藏鼠标、禁右键、出错自愈） |
| 双人同台 | `启动掌中戏.cmd duo` |
| 停止服务 | `停止掌中戏.cmd` |

- 全离线：three.js / MediaPipe wasm / 手势模型 / 皮影资产 / 音频全部本地；
- 必须走 `http://127.0.0.1:5173/`（摄像头要求安全上下文），不能双击 `index.html`；
- 自检：`camtest.html`（摄像头）、`audiotest.html`（音频）、`?debug=1`（实时面板）。

## 二、上传 GitHub（版本管理，建议做）

### 1. 初始化并提交

```bash
cd D:\lj\inktool\piying\shadow-play
git init -b main
git add .
git commit -m "掌中戲 · 手势皮影：手势驱动的数字皮影互动展项"
```

`.gitignore` 已经排除：`shots/`（74MB 开发截图，仓库只放 `docs/images/` 压缩版）、`_backup/`、日志、`.edge-kiosk/`。

提交后仓库约 **55–60MB**（vendor 41MB + models 15MB + puppets 2.3MB + audio 11.6MB 中的原声），单文件最大 12.9MB，**低于 GitHub 100MB 单文件上限**。

### 2. 建远程仓库并推送

在 GitHub 新建仓库（**建议先选 Private**），然后：

```bash
git remote add origin https://github.com/<你的账号>/shadow-play.git
git push -u origin main
```

> 首次推送需要凭据：用 GitHub 网页端生成 Personal Access Token 当密码，或安装 GitHub CLI（`gh auth login`）。

### 3. 公开前必须处理的版权（重要）

| 素材 | 来源 | 公开再分发的风险 |
| --- | --- | --- |
| `puppets/*.woop`（15 个皮影） | Woooo Piying Lab 官方资产库（可免费下载） | **需先确认其授权条款**：是否允许再分发/商用/公开托管 |
| `audio/bgm/*.mp3`（6 段戏剧原声） | 《夜深沉》《将军令》《牡丹亭·游园》《水龙吟》《万年欢》《良宵引》的演奏录音 | **商业录音，公网托管属于再分发**，风险明确，必须取得授权或替换 |
| `audio/lines/**`（31 句 AI 配音） | edge-tts 合成 | 一般可商用，但建议核对微软 TTS 使用条款 |
| `vendor/`、`models/` | three.js(MIT)、fflate(MIT)、MediaPipe(Apache-2.0) | 安全，保留许可证文件即可 |
| 代码 | 本项目 | 建议加 LICENSE（MIT 或 CC BY-NC-SA 视你的意愿） |

**两个安全做法（任选其一）：**

1. **仓库保持 Private**：只自己/团队用，参赛评审用本地演示或受控链接；
2. **公开但要"可公开版"**：
   - 取消 `.gitignore` 里 `audio/bgm/` 与 `puppets/` 的注释，把这两类素材排除；
   - 代码会在缺少音频时**自动回落到程序合成的氛围铺底**（`app/audio.js` 的 BGM 表），不会静音报错；
   - 皮影资产缺失会导致没有角色，所以更稳的做法是：**只公开代码 + 文档，资产私下提供**，README 里写清"运行需自行获取 .woop 资产"。

## 三、公网部署（Vercel / Netlify / Cloudflare Pages）

### 能跑吗？能，但有前提

- ✅ **摄像头**：平台默认给 HTTPS，满足 `getUserMedia` 的安全上下文要求；
- ✅ **静态站点**：本项目无构建步骤，直接托管即可；
- ⚠️ **必须配 COOP/COEP 响应头**：MediaPipe 多线程 wasm 需要 `SharedArrayBuffer`，缺头会退化甚至报错。仓库里已放好 `vercel.json`：

```json
"headers": [
  { "source": "/(.*)", "headers": [
    { "key": "Cross-Origin-Opener-Policy", "value": "same-origin" },
    { "key": "Cross-Origin-Embedder-Policy", "value": "require-corp" },
    { "key": "Cross-Origin-Resource-Policy", "value": "cross-origin" }
  ]}
]
```

Netlify 等价写法（`netlify.toml`）：

```toml
[[headers]]
  for = "/*"
  [headers.values]
    Cross-Origin-Opener-Policy = "same-origin"
    Cross-Origin-Embedder-Policy = "require-corp"
    Cross-Origin-Resource-Policy = "cross-origin"
```

### Vercel 部署步骤

```bash
npm i -g vercel      # 或直接 npx vercel
vercel login
vercel               # 预览环境
vercel --prod        # 正式环境
```

或最省事：GitHub 连 Vercel，选中仓库 → Deploy（无需填 build command，output 就是根目录）。

### 体积与首屏（公网体验的现实问题）

- 仓库 ~56MB，首屏会加载：手势模型 8.2MB + wasm 12.9MB + 皮影资产（按需）+ 音频（按出目懒加载）；
- 家宽/4G 下首屏大约 **10–30 秒**，且 Vercel 免费额度是 **100GB 流量/月**（约 2000–5000 次访问就会触顶）；
- 展馆现场**不要依赖公网**：断网即无法演示。公网只作为"评审/展示入口"。

### 想让公网更快，可以做的优化（未做，按需）

1. 把 `models/` 与 `vendor/` 放 CDN 或改用 jsDelivr；
2. 皮影资产改成"进哪出戏才加载哪两个角色"（现在是开场全加载 15 个）；
3. 截图/文档图不进部署包（已由 `.gitignore` 排除 `shots/`）；
4. wasm 用 `vision_wasm_internal.wasm` 单份（去掉 simd/nosimd 冗余，可省 ~25MB）。

## 四、我的建议

1. **现在就做**：`git init` + 本地提交（纯收益，能回滚、能对比）；
2. **GitHub 先建 Private**，等确认 Woooo 资产授权后再决定是否公开；
3. **展馆用本地部署**（已有快捷方式/开机自启/kiosk）；
4. **公网只部署"无原声版"**，并在页面或 README 注明素材来源与用途（参赛演示、非商用）；
5. 若主办方要求"可公开访问的在线地址"，优先用带访问控制的托管（Cloudflare Access / Netlify 密码保护），而不是完全公开。
