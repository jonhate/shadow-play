**【事实】未验证**：真机手势阈值（捏合/作揖/甩袖）、双人 4 手真机识别、多浏览器、长时运行、性能基准。

**【事实】Git 无法还原开发过程**：首次提交 `ade8003`（10-23 04:04）一次性导入 141 文件 / 116,055 行，此前的开发没有任何增量提交；19 个提交中 12 个是 10-23 18:00 之后的修复与材料。

**【评价】三个最值得记住的错误**（同一性质，反复三次）：
1. 甩袖阈值按"像素/秒"写（260/1400），实际单位是"画面宽/秒"→ 真实挥手永远达不到；
2. 转腕用绝对角 + 退化基线（拇指尖-食指尖，捏住时向量长度趋零）→ 举高时手腕乱转；
3. 作揖要求"两手都捏住且间距<0.14"→ 物理上做不到（两手贴近会丢手）。
**共性：把某个量的单位或性质当成了另一个量。三个都在提交前一晚集中暴露。**

**【事实】AI 侧的核心失误**：全部手势判定都用"注入的关键点数据"自测，理想数据不会退化、不会丢手，因此三个判定缺陷在自测中全部"通过"。

**【事实】用量**：`token-ledger.json` 记录 10-22 共 325 次请求 / 532 万输入 token / 23.2 万输出；10-23 仅 17 次 / 64.5 万输入 / 8.7 千输出。**该账本跨渠道汇总（10-22 涉及 12 个渠道）、且与当日实际交互量明显不符，不能归属到本项目**；API 费用无单价信息，**无法核实**。

**【评价】结论**：技术路线正确、交付完整、可复现；短板在**验收节奏**（真机验证滞后 36 小时）与**同类缺陷未做系统排查**。若重来，最高杠杆的改动不是换技术栈，而是"每个交互点做完立刻真机过 30 秒 + 同类量一次性排查"。

**【事实】** 做一个博物馆/非遗馆可用的皮影戏互动展项：观众用双手直接"耍"皮影，并用手势推进剧情。
**【推断】** 目标由三条线索共同确定：非遗传承诉求、展厅"只能看不能上手"的现状、以及现有手势展项与皮影操作逻辑无关。

# 9. 改进建议

## 9.1 技术路线

1. **判定层引入"量纲与量程"约束**：所有速度/距离阈值统一以"画面宽/秒""画面宽"为单位，并在代码中写明单位注释与合理量程（如速度 0~3），启动时打印一次自检值。
2. **动作建模从"瞬时"改为"过程"**：每个动作定义 `(特征, 阈值, 最短保持时间, 冷却时间)` 四元组，甩袖/作揖都按此实现，避免"检测到就消失"。
3. **关键几何量做退化检查**：使用任何"两点连线求角"前，先判断基线长度是否高于阈值（如 > 0.02 画面宽），否则改用更稳的基线。
4. **判定可现场校准**：做一个 `?calib=1` 页面，实时显示捏合值、双手距离、速度，现场 1 分钟调完阈值并导出。

## 9.2 Agent 协作方式

1. **自测必须分层**：逻辑层（注入数据）+ 手感层（真机）+ 交互层（人点一遍），三者缺一不可；AI 应主动声明"我只能做逻辑层"。
2. **同类排查一次做完**：修一个"单位错误"后，立即全仓扫描所有速度/距离阈值是否同一单位。
3. **每个交互点交付即真机**：功能做完立即让用户用 30 秒真机过一遍，再继续下一个。
4. **改代码同一次提交改文档**，并在提交信息中写"行为变更"。
5. **产物即时验证**：生成类脚本（PPT/文档/打包）每次运行后立刻回读校验（页数、字数、关键字、文件名）。
6. **回归前置**：在第二个交互点完成后就建立一键回归，而不是交付前。

## 9.3 验收机制

1. **开工即写验收单**：每条功能写成"操作 → 期望现象 → 判定方式"，例如"手横移 30cm，皮影手 0.3 秒内到位，误差 < 一个手掌宽"。
2. **真机验收记录表**：每次测试记录 时间 / 环境（光照、距离）/ 操作 / 现象 / 结论，并录 20 秒屏。
3. **三档视口 + 零报错作为门禁**：任何改动后跑 `node tools/verify-all.mjs`，失败不许继续。
4. **边界清单常驻**：维护一份"未验证清单"（真机阈值、双人 4 手、多浏览器…），提交前逐条确认表述一致。
5. **时间倒排**：T-3 完成材料、T-2 完成视频、T-1 只做验收与打包，禁止在 T-1 改核心逻辑。
