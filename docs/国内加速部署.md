# 国内访问加速：把大文件放到国内存储（网址不变）

> **2026-11-21 更新：已默认启用 jsDelivr，无需任何账号，开箱即用。**
> 现在点一下之后的 22MB 走 `https://cdn.jsdelivr.net/gh/jonhate/shadow-play-assets@main/`，
> 实测（热节点）**全部下完只用 11.4 秒**：模型 6.1MB / 637ms，wasm 只传 3.5MB / 325ms
> （jsDelivr 对 wasm 走 gzip，13.5MB 压到 3.5MB）。对照 GitHub Pages 国内直连 6–38KB/s，等于下不来。
> 素材镜像仓库：`jonhate/shadow-play-assets`（只放 puppets/models/wasm，24MB）。
> 为什么另开仓库：jsDelivr 对 gh 仓库有**整包 50MB 上限**，主仓库 130MB 会直接 403。
> 下文是一旦 jsDelivr 也不可用时的自建方案。

> 目标：**评委点的网址一个字都不改**（仍是 `https://jonhate.github.io/shadow-play/`），
> 但把"大文件"从 GitHub Pages 挪到国内对象存储，让点击后那 10MB 也能几秒下完。

---

## 一、先搞清楚现状（2026-11-06 实测）

| 阶段 | 真实传输（Pages 已 gzip） | 说明 |
| --- | --- | --- |
| 首屏（画幕出现） | **约 1.3 MB** | three.js 396KB + 第一出戏 5 个皮影 ~750KB + 代码 ~60KB |
| 点一下之后 | **约 10.4 MB** | 手势模型 6.4MB + wasm 4.0MB（首次点击才下载） |
| 台词配音 | 0 | 有戏剧原声时默认关闭，不再预取 31 个 mp3 |

国内直连 GitHub Pages 的问题在**大文件**：实测 110KB 的皮影包 3 秒能下，而 1.4MB / 8MB / 12.9MB 会超时到 0 字节。
所以首屏 1.3MB 一般能出来，**卡点在点击后那 10.4MB**。

---

## 二、要上传哪些文件

只上传"大文件"，页面代码仍留在 Pages：

```
puppets/                  （15 个 .woop + index.json，约 2.3MB）
models/gesture_recognizer.task   （8.2MB）
vendor/mediapipe/wasm/    （只上传 vision_wasm_internal.js/.wasm + vision_wasm_nosimd_internal.js/.wasm）
```

合计约 23MB（磁盘），传输时 gzip 后约 11MB。

> `vendor/mediapipe/wasm/vision_wasm_module_internal.*` 已在 2026-11-05 删除（浏览器从未请求它）。

---

## 三、开通与上传（以阿里云 OSS 为例，腾讯云 COS 同理）

1. 开通 OSS → 新建 Bucket，**读写权限：公共读**，地域选离评委近的（如杭州/上海）；
2. 把上面三类文件按原目录结构上传到一个前缀下，例如 `shadow-play/puppets/...`、`shadow-play/models/...`；
3. **必须配置 CORS**（这一步不做会整站白屏，实测过）：

```xml
<CORSConfiguration>
  <CORSRule>
    <AllowedOrigin>*</AllowedOrigin>
    <AllowedMethod>GET</AllowedMethod>
    <AllowedMethod>HEAD</AllowedMethod>
    <AllowedHeader>*</AllowedHeader>
    <ExposeHeader>Content-Length</ExposeHeader>
    <MaxAgeSeconds>86400</MaxAgeSeconds>
  </CORSRule>
</CORSConfiguration>
```

4. 记下访问域名，例如 `https://your-bucket.oss-cn-hangzhou.aliyuncs.com/shadow-play`

## 四、改一行代码就能切

`app/main.js` 顶部：

```js
const ASSET_BASE_DEFAULT = ''; // ← 改成你的地址，结尾不要带斜杠
// 例：const ASSET_BASE_DEFAULT = 'https://your-bucket.oss-cn-hangzhou.aliyuncs.com/shadow-play';
```

改完提交推送，GitHub Pages 重建后生效。

**临时验证（不改代码）**：地址后加参数即可

| 参数 | 作用 |
| --- | --- |
| `?assets=https://xxx.oss.../shadow-play` | 临时用这个前缀 |
| `?assets=0` | 强制走同源（回到 GitHub Pages） |

---

## 五、安全设计：配错也不会白屏

`app/main.js` 里做了回退：**如果 `ASSET_BASE` 的 `puppets/index.json` 取不到（404 / CORS 不通 / 超时），
自动回退同源**，只在控制台打一条警告：

```
[boot] 资源前缀不可用，回退同源（检查对象存储的 CORS 是否允许本站）
```

实测（2026-11-06）：故意把前缀指到一个没配 CORS 的地址 → 警告后正常启动，皮影照常加载。

## 六、成本

- OSS 标准存储：约 0.12 元/GB/月，**23MB 约等于 0 元**；
- 外网下行流量：约 0.5 元/GB；一次完整访问约 11MB → **约 0.006 元/次**；
- 1000 次评审访问 ≈ 6 元。

## 七、备选方案对比

| 方案 | 网址是否变 | 国内速度 | 成本/门槛 |
| --- | --- | --- | --- |
| **本方案：OSS/COS 放资源 + Pages 留页面** | **不变** | 点击后的 10MB 也快 | 需开通账号，几元 |
| Gitee Pages 全站镜像 | 会变（新网址） | 快 | 需实名开通；评委拿到的是旧网址，需另给链接 |
| Cloudflare 套 CDN | 不可能（github.io 不能 CNAME） | — | 不可行 |
| 只优化首屏（已做） | 不变 | 首屏 1.3MB 能出，点击后仍慢 | 0 元，已完成 |
| 评委用本地版 zip | — | 最快 | 需评委下载 |
